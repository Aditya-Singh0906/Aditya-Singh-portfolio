Every Terraform codebase eventually reaches a fork in the road. Either it becomes a set of small, opinionated modules — or a five-hundred-line `main.tf` that nobody wants to touch.

## The rule I follow

> A module should have one job and a small blast radius.

If a module provisions a VPC, that is what it does. It does not also create RDS instances because they "happen to live in that VPC."

## Module skeleton

```hcl
# modules/vpc/main.tf
resource "aws_vpc" "this" {
  cidr_block = var.cidr
  tags       = merge(var.tags, { Name = var.name })
}

resource "aws_subnet" "public" {
  count             = length(var.public_subnets)
  vpc_id            = aws_vpc.this.id
  cidr_block        = var.public_subnets[count.index]
  availability_zone = var.azs[count.index]
}
```

Each module ships with:

- Required `variables.tf` with sensible defaults
- A tight `outputs.tf` — only expose what callers actually need
- A short `README.md` explaining what the module does and does *not* do

## Environments are compositions

```hcl
module "vpc" {
  source          = "../../modules/vpc"
  name            = "prod"
  cidr            = "10.0.0.0/16"
  azs             = ["ap-south-1a", "ap-south-1b"]
  public_subnets  = ["10.0.1.0/24", "10.0.2.0/24"]
}
```

Environments should read like a story. If you cannot understand what a stack does in ten seconds, split it.

## The boring outcome

When modules are small, PRs stay small. When PRs stay small, reviews stay honest. When reviews stay honest, production stays boring.
